# ADR-0002 — Transcode videos asynchronously with fenced publication

**Status:** Proposed — review with the owner before marking accepted.

**Problem.** Serving uploaded originals made playback depend on browser codec support, while transcoding inside `POST /videos` added 4.42 seconds of CPU work to a request that took 4.78 seconds overall. We need to return control after the transfer, survive retries and worker crashes, and prevent two deliveries of the same job from publishing competing outputs.

**Considered.** (A) Keep FFmpeg in the web request for simple control flow. (B) Save a `queued` video, explicitly enqueue a Solid Queue job, and let a separate worker move it through `processing` to `ready` or `failed`. Within B, we considered holding a database lock for the full transcode versus using a short atomic claim plus a per-attempt fencing token; we also considered server-pushed status updates versus polling.

**Chose B** because the upload response no longer waits for CPU-heavy processing and Solid Queue uses the PostgreSQL infrastructure already present. `queued` means durable intent to process, `processing` means a worker owns a current attempt, `ready` means a separate `playback_file` was published, and `failed` is terminal for unsupported media. Operational failures retry three times. Workers create immutable, attempt-specific outputs; a short row lock and fencing-token check allows only the current owner to attach one, so a delayed worker cannot overwrite a newer result. A processing worker renews a 60-second application-level lease every 15 seconds, and a recurring reconciler re-enqueues expired leases because a hard-killed Solid Queue process cannot execute Active Job's exception retry path. The reconciler also recovers `queued` records left by a crash between the explicit controller save and enqueue. A false expiry can duplicate CPU work, but fencing keeps publication consistent. The M1 page polls only while work is non-terminal; realtime push is deferred until the roadmap introduces it for a measured need.
